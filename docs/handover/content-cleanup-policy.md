# Trip Talk — 教材クリーンアップ運用ルール

[引き継ぎの入口へ戻る](README.md)

更新日：2026-09-20

## 目的

正式教材が増えたときに、台本・表現・命名・学習ステータスの整理時期を忘れないようにする。

現在は、GitHub上の `data/scripts/*.json` を正式教材の正本とし、台本作成AIが必要に応じて検索する方式を優先する。

横断表現DBや要約DBは、今すぐ常設機能として実装しない。
教材本数が十分に増え、毎回すべての台本を読むコストが高くなった時点で、クリーンアップ兼索引作成として導入する。

## 節目ルール

### 正式教材 30本

**軽い棚卸しを行う。**

確認内容：

- LearningScript schemaの使い方にブレがないか
- scene / situation / summary / goal の書き方が極端にばらついていないか
- expressions の functions の付け方が一貫しているか
- learningStatus の new / reused の扱いに不整合がないか
- 台本ID命名規則に乱れがないか
- 不要な古い運用ルールや重複ドキュメントが残っていないか

原則として、この段階では横断DBを必須では作らない。

### 正式教材 50本

**要約DB・索引DBを作る必要があるか検討する。**

検討内容：

- 台本作成AIが毎回多数のJSONを読む負荷が大きくなっていないか
- 既習表現の検索に時間やトークンを使いすぎていないか
- 横断集計を毎回手動・AI検索で行うのが非効率になっていないか

必要性が低ければ、そのままGitHub検索運用を継続してよい。

### 正式教材 100本

**原則としてクリーンアップを実施する。**

実施候補：

- 全正式台本の一括走査
- expressionsの登場回数集計
- 登場台本一覧
- 対象ユーザー
- functions
- 再利用状況
- 重複・表記ゆれ・不整合の確認
- 必要に応じてAI検索用の要約DB / 索引DBを生成

要約DBは正本にしない。
正本は常に各 `data/scripts/*.json`。

例：

```text
data/
  scripts/
    MOTOKI0.json
    CHAMI0.json
    ...
  generated/
    expression-summary.json
```

## AIへの通知ルール

台本作成AIは、正式教材本数が以下の節目に到達した場合、通常の次台本作成に入る前にユーザーへ通知する。

- 30本：「軽い教材棚卸しの時期です」
- 50本：「要約DB / 索引DBを検討する時期です」
- 100本：「教材クリーンアップを実施する時期です」

通知だけで勝手に大規模変更しない。
ユーザー確認後に作業する。

## 数え方

正式教材本数は `data/scripts/*.json` の承認済み教材ファイル数で数える。

未承認台本、テストfixture、生成物、バックアップは含めない。

## 基本方針

- 今は個別JSONをきれいに積み上げる
- 検索はAIに任せる
- 早すぎる横断DB導入は避ける
- 必要になった時点で一括整理する
- 要約DBはAIが読みやすい索引として使う
- 要約DBができても元台本JSONを正本として残す

この文書を教材本数増加時のクリーンアップ判断基準とする。
