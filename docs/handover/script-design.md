# Trip Talk — 台本作成思想・運用ルール

更新日：2026-09-10

## 目的

Trip Talkの学習の中心は**台本／会話例を使った予習と反復**である。ChatGPT Liveは、その練習後に実戦形式で使えるかを確認するための練習場所として使う。

台本はアプリが自動生成するのではなく、ChatGPT上の専用プロジェクトでユーザーと戦略会議を行いながら設計する。

## 基本思想

- いきなり英文を大量生成しない。
- まず「この場面で最終的に何ができればよいか」を決める。
- 同じ場面を繰り返し、少しずつ広げる。
- 既習表現を多く残し、新規表現は少量ずつ追加する。
- 新しい内容を進める速さより、反射的に口から出ることを優先する。
- 相手の質問に答える力だけでなく、自分から質問する力も鍛える。
- 相づち、リアクション、聞き返し、確認、言い換えも正式な学習対象にする。
- 学ぶ英語の基準はアメリカ英語。ただし実戦ではノンネイティブを含む国際英語環境で通じることを優先する。
- 初期評価は「通じたか」。その後に自然さ、速さ、リンキング、省略への対応へ進む。
- 不自然でも通じる表現と、意味を壊す明確な誤りを区別する。

## 「台本作成」コマンド

ChatGPTの専用プロジェクトで、ユーザーが「台本作成」「次の台本」「台本を作ろう」等と言った場合は、完成台本を即座に出さず、以下の順番で進める。

### 1. 現在地確認

- どの場面・シーンか
- どこまで練習済みか
- 今回は反復か、少し広げるか
- すでに分かっている情報は質問し直さない

### 2. 過去データ確認

可能な限りTrip Talkの最新GitHubデータを参照し、対象ユーザーの過去台本・語句・既出表現を確認する。

確認対象：

- 既に登場した表現
- 再登場回数
- 複数場面で使える汎用表現
- 今回の場面で再利用すべき表現
- 今回新しく必要な表現

過去データへアクセスできない場合は、参照したふりをしない。

### 3. 戦略会議

必要な質問を数問ずつ返しながら設計を深める。

主な確認事項：

- この場面で最終的に何ができるようになりたいか
- 今回どこまで扱うか
- 既習表現
- 新規表現
- 自分から質問する場面
- 相づち・リアクション
- 聞き返し・確認・言い換え
- 前回から再利用する表現
- 今後別場面でも使う汎用表現

一度に質問を大量に並べない。

### 4. 学習設計の整理

台本を書く前に簡潔に整理する。

- 到達目標
- 今回の範囲
- 既習表現
- 新規表現
- 自分から質問するポイント
- リアクション・聞き返し
- 今回特に反復する表現

### 5. 台本作成

設計が固まってから台本を書く。

優先するもの：

- 実際にありそうな会話
- 短く明確で使いやすい英語
- ユーザー本人が実際に言いそうな内容
- アメリカ英語を基準にした自然な表現
- 国際的な旅行環境でも通じやすい表現
- 既習内容を多く残し、新規内容を少量にする

### 6. 品質チェック

完成前に確認する。

- ユーザーが話す量は十分か
- 相手に答えるだけの台本になっていないか
- 自分から質問する場面があるか
- 相づち・リアクションがあるか
- 聞き返し・確認・言い換えがあるか
- 既習表現が自然に再登場しているか
- 新規表現を詰め込みすぎていないか
- 現実の旅行で使う可能性が高いか
- 何度も反復する価値があるか

### 7. Liveへの接続

ChatGPT Liveは台本学習の中心ではない。台本を十分練習した後の実戦練習として使う。

Liveで以下が起きた場合は、次の台本設計へ戻す。

- 言いたかったが英語が出なかった
- 日本語で言った
- 「わからない」「パス」した
- 聞き返しができなかった
- 明確な重大ミスがあった

## 反復の考え方

同一テーマは一度きりで終わらせない。ホテルならホテルの中で、到着、フロント、荷物、部屋、電話、朝食、トラブル、チェックアウト等へ徐々に広げる。

目安としては既習80〜90%、新規10〜20%程度を基本思想とする。ただし固定比率ではなく、ユーザーの体感と実際の定着を優先する。

## 表現選定

重要度が高い表現：

- 複数場面で繰り返し使える
- ユーザーが実際に使う可能性が高い
- 前回必要だったのに出なかった
- 質問、確認、頼みごと、聞き返し、リアクションなど会話を前に進める

似た表現は意味の違いを保つ。

例：`I think` / `I guess` / `I suppose` を機械的に同一表現として統合しない。

## データベース運用の方向性

台本作成をChatGPTの記憶だけに依存させない。

最終的にはTrip TalkのGitHubに、台本と既出表現を正本として蓄積し、次の台本作成時に最新データを参照できる状態にする。

必要な仕組み：

1. 台本確定後、Trip TalkのGitHubへ保存
2. 台本データから横断表現DBを自動更新／再生成
3. 次回の「台本作成」ではその最新DBを参照
4. 新規表現だけで作らず、重要な既習表現を意図的に再登場させる

DBの具体的な保存形式・生成処理・自動更新方式は、現行Trip Talkのコードとデータ構造を棚卸しした上で決める。未確認のパスや実装を推測して作らない。

## 最重要ルール

**「台本作成」と言われたら、まず過去データ確認と戦略会議から開始する。**

ユーザーが明示的に「戦略会議なしで作って」と指示した場合のみ省略してよい。
