# Trip Talk — 台本作成思想・運用ルール

更新日：2026-09-25

## 目的

Trip Talkの学習の中心は**台本／会話例を使った予習と反復**である。ChatGPT Liveは、その練習後に実戦形式で使えるかを確認するための練習場所として使う。

台本はアプリが自動生成するのではなく、ChatGPT上の専用プロジェクトでユーザーと戦略会議を行いながら設計する。

## 基本思想

- いきなり英文を大量生成しない。
- まず「この場面で最終的に何ができればよいか」を決める。
- 同じ場面を繰り返し、少しずつ広げる。
- 既習表現を多く残し、新規表現は少量ずつ追加する。
- 新しい内容を進める速さより、反射的に口から出ることを優先する。
- 相手の質問に答える力だけでなく、自分から質問する力も鍛える。
- 相づち、リアクション、聞き返し、確認、言い換えも正式な学習対象にする。
- 学ぶ英語の基準はアメリカ英語。ただし実戦ではノンネイティブを含む国際英語環境で通じることを優先する。
- 初期評価は「通じたか」。その後に自然さ、速さ、リンキング、省略への対応へ進む。
- 不自然でも通じる表現と、意味を壊す明確な誤りを区別する。

## 再遭遇を中心にした学習設計

Trip Talkは、教材を次々に渡り歩く学習ではなく、限られた実用的な台本と表現を繰り返し使い、英語を「知っている」状態から「自然に出てくる」状態へ移すことを重視する。

基本方針：

- 新しい教材を無制限に増やすことを目的にしない
- 既存の台本を何度も繰り返し利用する
- 場面は必要に応じて追加する
- 新しい場面でも過去に学習した表現を積極的に再利用する
- 「新出表現の量」より「既習表現への再遭遇回数」を重視する
- 同じ英文をそのまま暗記するだけでなく、異なる場面で同じ語彙・文型・チャンクへ何度も遭遇させる
- 新台本は、まず既習資産から自然に再利用できるものを探し、それでも必要なものだけ新規表現として追加する

### Core 1000

日常生活・旅行で特に頻出する基本語彙約1000語を、単語帳として機械的に暗記するのではなく、Trip Talkの台本や会話の中で繰り返し使わせる構想を持つ。

例：`get`

- get there
- get back
- get a taxi
- get something to eat
- get a refund
- Could I get ...?
- I didn't get that.

Core 1000は単語単体ではなく、実際に使うチャンク・文型・定型表現の中で習得する。

目標は、

1. 聞いたり読んだりしたときに意味が分かる
2. 実際の会話で自分から使える

の2段階で、特に後者まで到達すること。

ただしCore 1000は「1000語をすべて台本へ機械的に入れるノルマ」ではない。自然な会話を壊してまで消化しない。台本設計では次の優先順位を基本とする。

1. その場面で本当に必要な表現
2. 過去の重要既習表現で自然に再利用できるもの
3. Core 1000のうち、その場面で自然に使える語・チャンク
4. それでも必要な新規表現

Core 1000との正式なタグ付け・coverage管理・専用DBは将来拡張とし、現時点では既存schemaやアプリ構造を大きく変更しない。

## 「台本作成」コマンド

ChatGPTの専用プロジェクトで、ユーザーが「台本作成」「次の台本」「台本を作ろう」等と言った場合は、完成台本を即座に出さず、以下の順番で進める。

### 1. 現在地確認

- どの場面・シーンか
- どこまで練習済みか
- 今回は反復か、少し広げるか
- すでに分かっている情報は質問し直さない

### 2. 過去データ確認

可能な限りTrip Talkの最新GitHubデータを参照し、対象ユーザーの過去台本・語句・既出表現を確認する。

確認対象：

- 既に登場した表現
- 再登場回数
- 複数場面で使える汎用表現
- 今回の場面で再利用すべき表現
- 異なる場面でも再遭遇させたい重要チャンク
- Core 1000候補として自然に使える語・チャンク
- 今回新しく必要な表現

過去データへアクセスできない場合は、参照したふりをしない。

### 3. 戦略会議

必要な質問を数問ずつ返しながら設計を深める。

主な確認事項：

- この場面で最終的に何ができるようになりたいか
- 今回どこまで扱うか
- 既習表現
- 再利用する表現
- Core 1000候補
- 新規表現
- 自分から質問する場面
- 相づち・リアクション
- 聞き返し・確認・言い換え
- 前回から再利用する表現
- 今後別場面でも使う汎用表現
- 今回意図的に再遭遇させる表現
- Core 1000候補として自然に使える語・チャンク

一度に質問を大量に並べない。

### 4. 学習設計の整理

台本を書く前に簡潔に整理する。

- 到達目標
- 今回の範囲
- 既習表現
- 新規表現
- 自分から質問するポイント
- リアクション・聞き返し
- 今回特に反復する表現

### 5. 台本作成

設計が固まってから台本を書く。

優先するもの：

- 実際にありそうな会話
- 短く明確で使いやすい英語
- ユーザー本人が実際に言いそうな内容
- アメリカ英語を基準にした自然な表現
- 国際的な旅行環境でも通じやすい表現
- 既習内容を多く残し、新規内容を少量にする

### 6. 品質チェック

完成前に確認する。

- ユーザーが話す量は十分か
- 相手に答えるだけの台本になっていないか
- 自分から質問する場面があるか
- 相づち・リアクションがあるか
- 聞き返し・確認・言い換えがあるか
- 既習表現が自然に再登場しているか
- 新規表現を詰め込みすぎていないか
- 現実の旅行で使う可能性が高いか
- 何度も反復する価値があるか

### 7. Liveへの接続

ChatGPT Liveは台本学習の中心ではない。台本を十分練習した後の実戦練習として使う。

Liveでうまく出なかった表現があっても、直ちに次の台本へ反映するとは限らない。まず同じ台本を反復すべき課題なのか、別台本で扱うべき課題なのかを本人が判断する。MVPではLiveの詳細失敗ログをTrip Talkへ自動保存しない。

Live終了時の講評は、その場で「良かった点」「改善点」「より自然な言い方」「次回意識する1〜3点」程度を確認できればよい。

## ChatGPT Liveでの読み上げモード

会話練習とは別に、確定台本をChatGPT Liveへそのまま読み上げさせる用途を持つ。目的はヒアリング練習と、発話できない場所での学習。

Trip Talkは音声再生を実装しない。Realtime API、音声API、ブラウザTTSも使わず、**読み上げ用の指示書を生成して外部ChatGPT Liveへ渡すだけ**とする。

最初の指示書には少なくとも以下を含める。

- 台本の質問→答えを記載順に、最初から最後まで読む
- 内容を変更・省略・追加・要約しない
- ユーザーの返答を待たず、教材音声として最後まで読む
- 読み終えたら終了する
- ユーザーがLive内で「もう一回」と言った場合は、直前と同じ台本を同じルールで最初から最後まで再読する

反復のたびにTrip Talkへ戻って指示書を再生成させない。最初の指示書を渡した後は、同じLive会話内でユーザーが「もう一回」と言うだけで再読する設計を基本とする。

## 反復の考え方

同一テーマは一度きりで終わらせない。ホテルならホテルの中で、到着、フロント、荷物、部屋、電話、朝食、トラブル、チェックアウト等へ徐々に広げる。

目安としては既習80〜90%、新規10〜20%程度を基本思想とする。ただし固定比率ではなく、ユーザーの体感と実際の定着を優先する。

## 表現選定

重要度が高い表現：

- 複数場面で繰り返し使える
- ユーザーが実際に使う可能性が高い
- 前回必要だったのに出なかった
- 質問、確認、頼みごと、聞き返し、リアクションなど会話を前に進める

似た表現は意味の違いを保つ。

例：`I think` / `I guess` / `I suppose` を機械的に同一表現として統合しない。

## GitHub参照と将来の要約DB

台本作成をChatGPTの記憶だけに依存させない。

現時点では、Trip TalkのGitHubに確定台本を正本として蓄積し、次の台本作成時にAIが必要な台本・既出表現を検索する方式を優先する。

横断表現DBやCore 1000 coverage DBは今すぐ常設実装しない。

教材本数が増えた場合は `content-cleanup-policy.md` の節目ルールに従い、必要になった時点で要約DB・索引DBを作る。要約DBは派生データであり、正本は各 `data/scripts/*.json` とする。

## 最重要ルール

**「台本作成」と言われたら、まず過去データ確認と戦略会議から開始する。**

ユーザーが明示的に「戦略会議なしで作って」と指示した場合のみ省略してよい。
