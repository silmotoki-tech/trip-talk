## 01 プロダクト設計書
更新日: 2026-09-07 / 版: 1.0

### 証拠の読み方
【指定仕様】今回ユーザーが明示した目標。実装済みを意味しない。
【会話復元】参照チャットの発言に基づく。過去のassistantの提案・推測は事実と区別する。
【コード確認】2026-09-07に取得したGitコミットで確認したもの。実機動作の保証ではない。
【未確認】証拠を回収できていないもの。【再開案】今回整理した提案で、過去の決定ではない。
参照元の発言IDは 11_原資料_参照チャット.md に全文収録する。

### 目的【指定仕様】
会話そのものを学習の中心に置き、同じ実際の場面を繰り返し、言えなかった英語を次の会話へ戻す。最優先はノンネイティブとの意思疎通。学ぶ英語はアメリカ英語を基準にする。通じる英語から、自然な表現、反射的な応答、速い会話・ネイティブの聞き取りへ進む。

### 学習ループ
本人と場面・範囲・難易度を選ぶ → 任意の予習5〜10項目 → Live 5〜10分 → 自動分析 → 良かった点・全改善点・重点課題・次回表現 → 本人が反復/拡張/変更を選ぶ → 同じ起点から新しい一巡。
Live内でスタッフや場所が変わることは許容するが、次巡は前巡の物語の続きにしない。内容の変化と学習履歴の継承を分ける。

### 反復と本人の主導権
重点課題は「前回必要だったが使えなかった表現」。予習も全改善点の学習も強制しない。AIが習得判定や進級を強制せず、範囲変更も本人が選ぶ。
以前の「既習80〜90%＋新規10〜20%」は会話内のassistantが示した目安。厳密な配合比・進級条件として確定していない。初期の習得スコア・自動卒業案は最新指定に優先しない。

### 学ぶ内容【会話復元】
場面固有語彙だけでなく、Sure / I see / Let me think / Could you say that again? など相づち・つなぎ・聞き返し・言い換えを育てる。通じたが不自然な英文を意思疎通不能と同じ失敗にしない。
複数場面で重複する表現を重要視し、類似表現はニュアンス差を残す「表現ファミリー」で整理する構想があった。詳細DB化・頻度スコアは将来構想で、MVP必須実装とは区別する。
英語は英語で保持し、説明は日本語。アクセントを誇張した物真似が目的ではない。

### 三つの系統を混ぜない
| 系統 | 性格 | 状態 |
|---|---|---|
| 今回のAPI＋Firebase構想 | Live→自動分析→履歴→次巡をアプリ内で完結 | 目標仕様。統合実装は未確認 |
| trip-talk | 予習・会話例・ChatGPTへ貼る指示書 | コード確認。READMEで有料Realtime凍結を明記 |
| Tamoyan-English | 台本を内蔵TTS等で反復するトレーナー | 別系統の関連資産。自動ステージ等を目標アプリへそのまま持ち込まない |

## 02 MVP仕様
更新日: 2026-09-07 / 版: 1.0

### 目標の必須範囲【指定仕様】
| 項目 | 要求 |
|---|---|
| 利用者 | タモやん、ゴンザエモンの2人。履歴・重点課題・設定を分離 |
| 端末 | 初期版はiPhone向け。ネイティブアプリかWeb/PWAかは目標仕様では未確定 |
| 場面 | タモやん=ホテル到着。ゴンザエモン=空港到着後の両替＋SIM購入 |
| 予習 | 任意5〜10項目。飛ばして同じ条件のLiveへ入れる |
| Live | 5〜10分。重大で意思疎通を妨げるミスのみ軽く訂正 |
| 詰まった場合 | 日本語回答、「わからない」、パスを許容 |
| 起点 | 毎巡同じ起点。続き物にしない |
| 振り返り | 良かった点、全改善点、重点課題、次回使う表現、任意で全文ログ |
| 重点課題 | 前回必要だったが使えなかった表現 |
| 次巡 | 同じ範囲をもう一度 / 少し広げる / 場面を変える |
| 難易度 | 本人が10段階設定。速度、リンキング/省略、聞き取り難度等 |
| 分析・保存 | RealtimeでLive、通常GPT APIで終了後分析、Firebase等で分離保存 |

### 画面の振る舞い【会話復元】
ホームには利用者・現在の場面・難易度・前回の重点課題・開始導線。予習は少量の表現を確認する場。Liveは会話に集中できる表示。振り返りには全改善点を残すが、すべてを暗記しなければ次へ行けない制御は置かない。全文ログは折りたたみ等で任意表示する。
認証は会話でログインを使う方向が示唆されたが、Googleログインなど方式は未決定。

### 後回し
発音評価、履歴一覧・グラフ、詳細な習得スコア、「これを覚えたい」の実機能。最後の機能は動作しないボタンのプレースホルダー可。未動作だと分かる表示が望ましい【再開案】。
会員課金、大量ユーザー対応、全端末の最適化は初期2人用スコープに含めない。

### 受入チェック【再開案・未実施】
1. 2人がそれぞれの場面で一巡を完了できる。
2. 予習を飛ばせる。Live開始時に選んだ難易度が渡る。
3. 日本語/パスで会話が止まらず、該当箇所が振り返りに残る。
4. 意思疎通できた別表現を単なる台本不一致で誤りにしない。
5. 前巡の未使用表現が次巡に自然に再登場する。
6. 次巡も同じ起点。本人の同意なしに範囲・難易度が上がらない。
7. 良かった点・全改善点・重点課題・次回表現・ログを確認できる。
8. 2人のデータが混ざらない。保存・分析失敗時に記録を失わない。
9. iPhoneで音声許可、割り込み、終了、再開、音声停止を確認する。
複数巡（過去assistant提案では各5〜10巡）の試用を行い、実測結果を別途記録する。

### 現存trip-talkとの差分【コード確認】
アプリ内の画面状態はhome/preview。Realtime接続・分析API・Firebaseの実働経路は見つからない。SessionRecord型やsaveSession関数、realtimeInstructions関数があることだけではLive実装済みとしない。
現在の指示書は「第○周」「総評2〜3文」「次回の課題1文」で、目標の全改善点一覧とは異なる。ホテル5場面、空港5場面の定義があり、READMEの空港3場面は古い。表示名はゴンザエモンではなく「ちゃみ」。

## 04 教材・台本設計思想
更新日: 2026-09-09 / 版: 1.0

### TripTalkの目的
TripTalkは旅行英語を極めるための教材ではない。旅行という具体的で実践的な場面を使い、CEFR B2程度までの汎用的な英会話能力を育てる。特殊なケースを除けば旅で困らず、旅行以外でも言いたいことをある程度言え、英語を理由に海外へ行くことを尻込みしない状態を目標とする。

ホテル、空港、レストラン等は「攻略対象」ではなく、英語力を育てるための舞台とする。ホテル固有の高度な表現を掘るより、別場面へ横展開して汎用表現を使い直す方を優先する。

### 英語の基準
- 基本はアメリカ英語。
- ただしネイティブらしさ自体を目的にせず、現地で通じやすく自然な英語を優先する。
- A1〜B2の頻用域を厚くする。C1/C2相当の表現は、その場面で一般的に使う場合を除き初期優先度を下げる。
- 学習が進み新規学習が少なくなった段階で、高度表現を追加するかは都度相談して決める。

### 台本は本数から作らない
1シーン5本などの固定本数を先に決めない。まず制作前の作戦会議で、その場面からどの程度の汎用英語を学べるかを棚卸しし、そこから必要な台本数を逆算する。

たとえばホテルフロントが教材価値の高い場面なら10本作ってもよい。逆に教材価値の低い場面は2〜3本で切り上げる。Hotel 1〜10の後に、さらにホテル固有の上級表現へ進む必要はなく、Restaurant 1〜2など別の易しい場面へ移ってよい。難易度はシーン番号と一致させない。

### 最初の1〜2本は最低限の突破力
各シーンの最初の1〜2本は「これが分かって言えれば最低限その場面を突破できる」という内容で固める。序盤から学習密度を欲張りすぎない。

その後の台本で、より自然な言い方、別表現、汎用フレーズ、新しい語彙、質問力、リアクションを追加していく。

### 作戦会議で先に決める獲得目標
台本本文を書く前に、少なくとも以下を洗い出す。

1. 自分が話せるようにする汎用フレーズ
2. 自分が使えるようにする語彙・熟語
3. 相手から言われたら理解すべき表現
4. 相手から言われたら理解すべき語彙
5. その場面固有だが最低限必要な英語
6. 会話を自然につなぐリアクション・相槌
7. 自分から情報を取りにいく質問力・情報獲得力

台本はこの獲得目標から逆算して作る。

### 能動英語と受動英語を分ける
自分側のセリフは、自分で英作文して発話できることを目標とする。相手側のセリフは、聞いて意味を理解できることを主目標とする。

ただし相手側で使われる重要語彙・重要フレーズも学習対象に含める。自分が言う必要はなくても、聞いて分からなければ会話が成立しないため。

### 予習台本を瞬間英作文教材にする
別個の瞬間英作文教材を大量に作るのではなく、予習台本にある自分側のセリフをそのまま瞬間英作文として使う。日本語を見て英語を発話し、その後に模範英文を確認する。

一つの日本語に複数の自然な正解を認める。必要に応じて回答欄に「その他の自然な言い方」を併記する。

### 音読
台本はロールプレイ準備だけでなく、繰り返し音読する教材として作る。100回きっかりを強制しないが、考えず口から出るまで何度も声に出す学習法を重視する。

実装が容易なら手動の音読カウンターを付けてもよい。回数管理自体は主目的にしない。

### 質問力を意図的に鍛える
通常のロールプレイでは「相手に聞かれて答える」練習に偏りやすい。TripTalkでは、自分から必要な情報を取りにいく能力を独立した学習目標とする。

AIが毎回「何か質問はありますか？」と誘導するのではなく、会話上はそのまま終われる場面でも、学習者が必要に応じて自分から質問を起こす構造を入れる。

基本形は「情報が必要になる → 自分から質問する → 相手の返答を理解する → 自然にリアクションする」とする。

### リアクションも学習対象
Sure / I see / Got it / Sounds good / Perfect / That's fine / No problem などのリアクション・相槌は飾りではなく英会話能力の一部として扱う。質問→回答だけの機械的な会話にならないよう、自然な反応を台本に含める。

### 同じ表現は何度出てもよい
DUOのように少ない教材に重要な語彙・表現を高密度で入れる考え方は参考にするが、TripTalkでは一度出た表現を再登場させない必要はない。

むしろ I'd like to... / Could I...? / Is there...? のような汎用フレームを、異なる場面・異なる語彙で何度も使う。目的は例文暗記ではなく「単語を入れ替えれば別場面でも使える型」の習得である。

### 反復は自然さを優先する
既習表現を何％入れるといった固定比率は設けない。その場面で自然なら再利用し、不自然なら無理にねじ込まない。

一方、教材DBには初出・登場シーン・登場回数・最終登場などを持たせられる設計とし、重要表現がしばらく使われておらず、新しい場面で自然に使えるなら復習として入れる。

これは学習者本人の習得度追跡とは別物。個々の正答率や習得スコアの詳細追跡は、初期実装では必須にしない。

### 英文データベースを制作の地図にする
今後の台本は、その場面だけを見て単発で作らない。TripTalkで扱った英文・中核フレーズ・主要語彙・自分側/相手側・使用シーン・おおよそのCEFRなどを参照できる教材DBを制作の地図として使う。

基本フロー：
既存教材DB確認 → 既習内容確認 → 今回の新規獲得目標を決定 → 自然に再利用できる既習表現を確認 → 必要本数を決定 → 人間とAIで壁打ち → 台本確定。

AIに「この場面の会話を作って」と丸投げし、自動で完成台本を量産しない。教材全体の地図を見ながら人間とAIが共同で設計する。

### 自然さと学習密度
学習価値を高めるために語彙や構文を詰め込むことは重要だが、実際には言わないような不自然な会話にはしない。

優先順位は「その場面で自然に成立する英語」＋「その範囲で可能な限り汎用性と学習密度を高める」とする。

### 中核原則
シーンを攻略するために英語を学ぶのではない。
英語を身につけるために、旅行というシーンを利用する。
