## 01 プロダクト設計書
更新日: 2026-09-07 / 版: 1.0

### 証拠の読み方
【指定仕様】今回ユーザーが明示した目標。実装済みを意味しない。
【会話復元】参照チャットの発言に基づく。過去のassistantの提案・推測は事実と区別する。
【コード確認】2026-09-07に取得したGitコミットで確認したもの。実機動作の保証ではない。
【未確認】証拠を回収できていないもの。【再開案】今回整理した提案で、過去の決定ではない。
参照元の発言IDは 11_原資料_参照チャット.md に全文収録する。

### 目的【指定仕様】
会話そのものを学習の中心に置き、同じ実際の場面を繰り返し、言えなかった英語を次の会話へ戻す。最優先はノンネイティブとの意思疎通。学ぶ英語はアメリカ英語を基準にする。通じる英語から、自然な表現、反射的な応答、速い会話・ネイティブの聞き取りへ進む。

### 学習ループ
本人と場面・範囲・難易度を選ぶ → 任意の予習5〜10項目 → Live 5〜10分 → 自動分析 → 良かった点・全改善点・重点課題・次回表現 → 本人が反復/拡張/変更を選ぶ → 同じ起点から新しい一巡。
Live内でスタッフや場所が変わることは許容するが、次巡は前巡の物語の続きにしない。内容の変化と学習履歴の継承を分ける。

### 反復と本人の主導権
重点課題は「前回必要だったが使えなかった表現」。予習も全改善点の学習も強制しない。AIが習得判定や進級を強制せず、範囲変更も本人が選ぶ。
以前の「既習80〜90%＋新規10〜20%」は会話内のassistantが示した目安。厳密な配合比・進級条件として確定していない。初期の習得スコア・自動卒業案は最新指定に優先しない。

### 学ぶ内容【会話復元】
場面固有語彙だけでなく、Sure / I see / Let me think / Could you say that again? など相づち・つなぎ・聞き返し・言い換えを育てる。通じたが不自然な英文を意思疎通不能と同じ失敗にしない。
複数場面で重複する表現を重要視し、類似表現はニュアンス差を残す「表現ファミリー」で整理する構想があった。詳細DB化・頻度スコアは将来構想で、MVP必須実装とは区別する。
英語は英語で保持し、説明は日本語。アクセントを誇張した物真似が目的ではない。

### 三つの系統を混ぜない
| 系統 | 性格 | 状態 |
|---|---|---|
| 今回のAPI＋Firebase構想 | Live→自動分析→履歴→次巡をアプリ内で完結 | 目標仕様。統合実装は未確認 |
| trip-talk | 予習・会話例・ChatGPTへ貼る指示書 | コード確認。READMEで有料Realtime凍結を明記 |
| Tamoyan-English | 台本を内蔵TTS等で反復するトレーナー | 別系統の関連資産。自動ステージ等を目標アプリへそのまま持ち込まない |

## 02 MVP仕様
更新日: 2026-09-07 / 版: 1.0

### 目標の必須範囲【指定仕様】
| 項目 | 要求 |
|---|---|
| 利用者 | タモやん、ゴンザエモンの2人。履歴・重点課題・設定を分離 |
| 端末 | 初期版はiPhone向け。ネイティブアプリかWeb/PWAかは目標仕様では未確定 |
| 場面 | タモやん=ホテル到着。ゴンザエモン=空港到着後の両替＋SIM購入 |
| 予習 | 任意5〜10項目。飛ばして同じ条件のLiveへ入れる |
| Live | 5〜10分。重大で意思疎通を妨げるミスのみ軽く訂正 |
| 詰まった場合 | 日本語回答、「わからない」、パスを許容 |
| 起点 | 毎巡同じ起点。続き物にしない |
| 振り返り | 良かった点、全改善点、重点課題、次回使う表現、任意で全文ログ |
| 重点課題 | 前回必要だったが使えなかった表現 |
| 次巡 | 同じ範囲をもう一度 / 少し広げる / 場面を変える |
| 難易度 | 本人が10段階設定。速度、リンキング/省略、聞き取り難度等 |
| 分析・保存 | RealtimeでLive、通常GPT APIで終了後分析、Firebase等で分離保存 |

### 画面の振る舞い【会話復元】
ホームには利用者・現在の場面・難易度・前回の重点課題・開始導線。予習は少量の表現を確認する場。Liveは会話に集中できる表示。振り返りには全改善点を残すが、すべてを暗記しなければ次へ行けない制御は置かない。全文ログは折りたたみ等で任意表示する。
認証は会話でログインを使う方向が示唆されたが、Googleログインなど方式は未決定。

### 後回し
発音評価、履歴一覧・グラフ、詳細な習得スコア、「これを覚えたい」の実機能。最後の機能は動作しないボタンのプレースホルダー可。未動作だと分かる表示が望ましい【再開案】。
会員課金、大量ユーザー対応、全端末の最適化は初期2人用スコープに含めない。

### 受入チェック【再開案・未実施】
1. 2人がそれぞれの場面で一巡を完了できる。
2. 予習を飛ばせる。Live開始時に選んだ難易度が渡る。
3. 日本語/パスで会話が止まらず、該当箇所が振り返りに残る。
4. 意思疎通できた別表現を単なる台本不一致で誤りにしない。
5. 前巡の未使用表現が次巡に自然に再登場する。
6. 次巡も同じ起点。本人の同意なしに範囲・難易度が上がらない。
7. 良かった点・全改善点・重点課題・次回表現・ログを確認できる。
8. 2人のデータが混ざらない。保存・分析失敗時に記録を失わない。
9. iPhoneで音声許可、割り込み、終了、再開、音声停止を確認する。
複数巡（過去assistant提案では各5〜10巡）の試用を行い、実測結果を別途記録する。

### 現存trip-talkとの差分【コード確認】
アプリ内の画面状態はhome/preview。Realtime接続・分析API・Firebaseの実働経路は見つからない。SessionRecord型やsaveSession関数、realtimeInstructions関数があることだけではLive実装済みとしない。
現在の指示書は「第○周」「総評2〜3文」「次回の課題1文」で、目標の全改善点一覧とは異なる。ホテル5場面、空港5場面の定義があり、READMEの空港3場面は古い。表示名はゴンザエモンではなく「ちゃみ」。

## 03 ユーザー別シナリオ
更新日: 2026-09-07 / 版: 1.0

### タモやん【指定仕様】
起点はホテル到着。まずフロント周辺で、チェックイン・予約名・必要情報の確認を反復する。
【会話復元の展開例】予約確認、部屋の希望、朝食時間、荷物預け。本人が広げると選んだら客室、Wi-Fi、電話、タオル依頼、廊下の雑談、トラブル、チェックアウトへ。毎巡は到着に戻し、前回の続きとして「翌朝から」等にしない。

### ゴンザエモン【指定仕様】
起点は空港到着後。両替とSIM購入を中心にする。
【会話復元の展開例】両替所を探す→レート/手数料/受取額を確認→両替→SIM売場を探す→期間/容量/料金を確認→SIM/eSIM・設定・開通確認。
初期範囲や一巡でどこまで扱うかは5〜10分と本人選択に合わせる。旅先、金額、SIM条件は架空の練習用条件であり、現実の料金や設定の助言ではない。

### 共通の会話能力
聞き返す、意味を確認する、簡単な別表現に言い換える、相づち、考える時間を取る。日本語で言いたい意図を補足してもよい。
前巡で言えなかった例「Could I have a receipt?」を次巡の両替で再登場させる【再開例】。この例は本人の実際の失敗ログではない。

### 現存trip-talkの場面
シナリオの正確な名称・英語例文・日本語訳・語彙・展開はソースZIP内の src/lib/scenarios.ts を原本とする。ホテルはチェックイン/朝食/廊下の雑談/客室トラブル/チェックアウト。空港は入国審査/両替/SIM購入/SIM設定支援/ニャチャン空港バスの5場面。
現在は選択した各場面の起点へ戻る仕組みで、ホテル到着・空港到着からの連続範囲という目標とは要調整。
