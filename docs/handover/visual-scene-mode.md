# Trip Talk — 視覚シーン練習 / 静止画方針

[引き継ぎの入口へ戻る](README.md)

更新日：2026-09-23

## 位置づけ

Trip Talkでは、現在のテキスト中心の台本練習に加えて、**場面に合う静止画による視覚シーン練習**を採用する。これは制作方針の変更であり、既存アプリの静止画化が完了したことを意味しない。

これは単なる装飾ではなく、

**テキストを思い出す → 場面を見たら英語が出る**

へ学習を発展させるための補助レイヤーとして位置づける。

現行の正本である `dialogue` / `expressions` は変更しない。視覚演出は別メタデータとして管理し、英語教材と演出を独立して修正できる構造を維持する。

## 将来の学習フロー

基本の発展形は次のとおり。

1. テキストで予習・反復
2. 質問だけで練習
3. **場面に合う静止画で状況想起**
4. ChatGPT Liveで実戦

視覚モードは「質問だけで練習」を、より状況依存の想起へ進化させたものとして考える。

## 基本アイデア

- 参考画像のキャラクターデザインを全場面で維持する
- 顔・体型・線の雰囲気を保ち、ポーズ・向き・視線は会話と小物の関係に合わせる
- アニメーションや自動コマ送りは使わず、場面を静止画で表す
- 一目で状況が分かり、発話の邪魔をしないことを優先する

過去の「顔を消す」「胴体を縦線だけにする」「極端に簡略化する」「offer / receive / confirmのアニメーションを維持する」という指示は撤回する。

## 場面に合うポーズ

手を差し出す、荷物を示す、紙を渡すなど、会話に必要な動作の意味を静止ポーズで表す。体・顔の向き、視線、手の位置は場面ごとに決める。見本の立ち姿を使い回さない。

動きを補間するループやアニメーションは不要。将来、会話の進行に応じて画像を切り替える場合も静止画として扱う。

## 目指す学習UI

視覚モードでは、音声はアプリ内に入れない。

基本画面：

- 上部：棒人間・背景・小物による視覚シーン
- 下部：partner側の英語発話
- learner側の返答は初期状態では非表示
- 「答えを見る」で直後のlearner発話を表示
- 「次へ」で次の発話／場面へ進む

文字は最初は**画面下部の固定表示**を基本とする。
吹き出しや中央表示は将来の表現オプションとして検討するが、初回実装では必須にしない。

学習の中心は、

**場面を見る**
→ **相手の英語を読む**
→ **自分の返答を記憶から取り出して声に出す**

である。

learner側の答えを常時表示して、単なる読み上げ練習にはしない。

将来的には、

- Level 1：partner全文表示
- Level 2：partner文を一部省略
- Level 3：文字なし・場面だけ

のように文字依存を減らす発展も検討できる。

## 音声方針

Trip Talkの視覚モードでは**音声再生を実装しない**。

理由：

- TTSや音声ファイル管理を増やさない
- iPhone上の挙動とUIを単純に保つ
- Trip Talkは視覚＋文字の想起練習、ChatGPT Liveは実際の音声会話、と役割分担できる

## キャラクターと小物

人物と小物は、自然な位置関係で配置する。荷物の輪郭が人物の胴体を突き抜けるなど、不自然な重なりを避ける。

素材の部品化や共通化は必須にしない。まず参考画像に合う静止画1枚を確認し、必要になってから再利用方法を検討する。

## 学習上の狙い

主役は映像ではなくユーザーの発話。

基本構造は、

**場面の静止画**
→ **partner発話**
→ **ユーザーが発話**

とする。

映像を眺める教材にはしない。視覚刺激を英語発話のトリガーとして使う。

## デザイン方針

AI生成画像は基本的に使わない。

理由：

- 教材ごとに絵柄が変わる
- キャラクターの見た目が安定しない
- 不自然な画像が混ざる可能性がある
- 教材全体の統一感が崩れる
- ファイル容量と管理コストが増えやすい

代わりに、棒人間・背景・小物を共通フォーマットで統一する。

優先するもの：

- 一目で状況が分かる
- 少し和む
- 発話の邪魔をしない
- 全教材で統一感がある

## 標準キャラクター参考画像

![Trip Talk 標準キャラクター参考画像](assets/stick-figure-reference.png)

この画像が完成見本。**顔、頭と胴体の形・比率、手足の表現、線の太さや雰囲気**を人物デザインの基準とする。顔を消したり、胴体を縦線だけにしたり、独自のキャラクターに描き直したりしない。

**Cursor / Grokは人物の制作前に、必ず `docs/handover/assets/stick-figure-reference.png` を開いて確認すること。文章だけで再解釈しない。** 画像を確認できない場合は推測で制作せず、その事実を報告する。

**固定するのはキャラクターデザインであり、ポーズや向きではない。** 体・顔の向き、視線、腕や手の位置は、場面の会話と相手・小物との関係に合わせる。

構図はlearner本人から見た**一人称視点**を基本とする。見本はpartnerやスタッフなど相手キャラクターに適用する。learnerの頭・胴体・全身は原則描かず、必要な場合のみ手や荷物を手前に配置する。全身を収めるために相手を不自然に小さくしたり、learnerとpartnerを横並びにした第三者視点へ戻したりしない。

## 実装方針

まずアプリから独立した静止画プレビューを作り、見本と並べてユーザーの確認を受ける。SVGを使う場合も静止表示とし、素材形式より見本との一致を優先する。

アプリへの組み込みは見た目の了承後の別作業とする。既存のアニメーション廃止もその段階で行い、今回のプレビュー作業ではアプリコードを変更しない。大量のMP4/GIFやアニメーション用の仕組みは追加しない。

## 容量の考え方

教材数が増えても重くなりすぎないことを優先する。

目標イメージ：

- 1場面あたり数十KB〜数百KB程度
- 共通SVGや小物を再利用
- 動画ファイルを大量保存しない

厳密な上限値は試作後に決める。

## データ設計

正式な `LearningScript` schema の `dialogue` / `expressions` に視覚演出情報を混ぜない。

英語教材の正本：

- dialogue
- expressions

視覚演出は別管理。

将来の演出メタデータ候補：

- scene背景
- 使用キャラクター
- 使用小物
- pose

必要なら台本IDなどで紐づける。

## 初回試作

**今回の対象は、MOTOKI0のHotelEntranceSceneのoffer状態に対応する静止画1枚のみ。**

対象の発話：

> Welcome to the Grand Hotel. May I help you with your bags?

構図と内容：

- learnerの目の前にいるスタッフが、こちらへ話しかけて荷物を運ぶことを申し出ている
- スタッフの顔や体はこちらを向き、手は荷物を示す、または荷物へ自然に差し出す
- 荷物はlearner側の手前にあり、まだスタッフへ渡していない
- 背景はホテル入口と分かる最低限
- 一人称視点と参考画像のキャラクターデザインを維持する

receive / confirm、3組目以降、他台本への展開は今回行わない。

## 実装の進め方

1. 対象repo・branch・git statusを確認し、既存の未コミット変更を保持する。
2. 参考画像を実際に開いて確認する。
3. 既存素材を上書きせず、アプリから独立した新しいプレビュー素材としてofferの静止画を1枚作る。
4. 参考画像と並べたプレビュー、作成ファイル、見本との差や未確認事項だけを簡潔に報告する。
5. ここで止めてユーザーの確認を待つ。アプリへの組み込みや他の場面へ進めない。

今回の制作作業では、HotelEntranceSceneの実装、CSS、dialogue、台本JSON、schema、Firebase、visualIndex、回答表示、「答えを見る」「次へ」、引き継ぎ文書を変更しない。commit / pushもしない。

プレビュー段階ではアプリ全体のlint / build / testは不要。組み込みを依頼された段階で、必要なコード検証と320pxでの表示・操作確認を行う。

Cursor / Grokへの指示は1回につき原則1タスクとし、今回の到達点をプレビュー提示までに限定する。

## 台本作成プロジェクトとの役割分担

現時点では、台本作成プロジェクトの正式出力仕様にvisual metadataをまだ組み込まない。

まずMOTOKI0の試作で、

- どのvisual metadataが本当に必要か
- 1場面と1発話の対応をどうするか
- どのポーズや小物を再利用するか
- どの小物情報が必要か

を確認する。

試作後に仕様を固定し、その時点で台本作成プロジェクトへ、

- 背景
- 登場人物
- 小物
- partner action
- learner action
- text placement
- visual step

などの演出設計出力を追加するか判断する。

## 実装タイミング

現在の制作上の到達点は、ホテル入口の静止画1枚を見本と比較して確認する段階。既存アプリの実装完了や検証済みを意味しない。

この文書更新は方針整理のみ。実際の画像制作・アプリ変更は別作業とする。

## 守ること

- 映像を豪華にしすぎない
- 画像生成を教材制作の必須工程にしない
- dialogue / expressionsを壊さない
- 視覚演出のために学習仕様を複雑化しない
- 動画ファイル中心の重い構成にしない
- まず静止画1枚を提示し、ユーザーの見た目の確認後に次の作業を決める

この文書を将来実装時の振り返り資料とする。
