# Trip Talk — 視覚シーン練習 / アニメーションモード構想

[引き継ぎの入口へ戻る](README.md)

更新日：2026-09-20

## 位置づけ

Trip Talkでは、現在のテキスト中心の台本練習に加えて、将来的に **視覚シーン練習 / アニメーションモード** を追加する構想がある。

これは単なる装飾ではなく、

**テキストを思い出す → 場面を見たら英語が出る**

へ学習を発展させるための補助レイヤーとして位置づける。

現行の正本である `dialogue` / `expressions` は変更しない。視覚演出は別メタデータとして管理し、英語教材と演出を独立して修正できる構造を維持する。

## 将来の学習フロー

基本の発展形は次のとおり。

1. テキストで予習・反復
2. 質問だけで練習
3. **棒人間アニメ付きで状況想起**
4. ChatGPT Liveで実戦

視覚モードは「質問だけで練習」を、より状況依存の想起へ進化させたものとして考える。

## 基本アイデア

- 全教材で統一した棒人間表現を使う
- リアル人物画像やAI生成画像を教材ごとに作らない
- 1場面につき2〜3コマ程度の粗いコマ送り、または1〜2秒程度の短いループアニメーション
- 滑らかさよりも、少しカクカクした動きで親しみやすさを出す
- 「豪華な映像」ではなく、一目で状況が分かることを優先する
- 発話を邪魔しない

このカクカク感は、教材の堅さを和らげ、Trip Talk独自の視覚的な個性・ブランド要素にもなり得る。

## 想定する最小動作

複雑なアニメーションは不要。以下のような動きを共通部品化する。

- 手招きする
- うなずく
- 指差す
- 紙を差し出す
- お金を渡す
- お金を受け取る
- お金を数える
- 顔や体の向きを少し変える

たとえばCHAMI0の空港両替なら、

1. スタッフがこちらを見て手招き
2. ユーザーがカウンターに近づく
3. スタッフが紙幣や用紙を指差す

程度で十分。

## 学習上の狙い

主役は映像ではなくユーザーの発話。

基本構造は、

**相手の動き**
→ **partner発話**
→ **ユーザーが発話**

とする。

映像を眺める教材にはしない。視覚刺激を英語発話のトリガーとして使う。

## デザイン方針

AI生成画像は基本的に使わない。

理由：

- 教材ごとに絵柄が変わる
- キャラクターの見た目が安定しない
- 不自然な画像が混ざる可能性がある
- 教材全体の統一感が崩れる
- ファイル容量と管理コストが増えやすい

代わりに、棒人間・背景・小物を共通フォーマットで統一する。

優先するもの：

- 一目で状況が分かる
- 少し和む
- 発話の邪魔をしない
- 全教材で統一感がある

## 実装方針

大量のMP4/GIFを教材ごとに持つ方式は避ける。

優先候補：

- SVG
- 共通画像パーツ
- CSSアニメーション
- JavaScriptによる簡単なポーズ切り替え

共通素材例：

- `person.svg`
- `counter.svg`
- `money.svg`
- `paper.svg`

教材ごとには大きな画像を保存せず、ポーズや表示順だけを指定する方向。

例：

通常姿勢
→ 手を上げる
→ 少し手前に振る
→ 通常姿勢

## 容量の考え方

教材数が増えても重くなりすぎないことを優先する。

目標イメージ：

- 1場面あたり数十KB〜数百KB程度
- 共通SVGや小物を再利用
- 動画ファイルを大量保存しない

厳密な上限値は試作後に決める。

## データ設計

正式な `LearningScript` schema の `dialogue` / `expressions` に視覚演出情報を混ぜない。

英語教材の正本：

- dialogue
- expressions

視覚演出は別管理。

将来の演出メタデータ候補：

- scene背景
- 使用キャラクター
- 使用小物
- pose
- animationType
- loop
- duration

必要なら台本IDなどで紐づける。

## 初回試作

最初から大規模システムにしない。

最初の試作候補は **CHAMI0「空港での両替」**。

最小構成：

- 棒人間
- カウンター
- お金
- 手招きアニメ

これだけで「場面を見たら英語が出る」体験が成立するか確認する。

良ければ次に共通部品化・他教材展開を行う。

## 実装タイミング

現時点では実装しない。

まず、

- MOTOKI0
- CHAMI0
- 現在の通常練習フロー

が安定して動くことを優先する。

視覚モードはその後の拡張機能として扱う。

## 守ること

- 映像を豪華にしすぎない
- 画像生成を教材制作の必須工程にしない
- dialogue / expressionsを壊さない
- 視覚演出のために学習仕様を複雑化しない
- 動画ファイル中心の重い構成にしない
- まず1場面だけ試作し、学習効果と操作感を確認してから拡張する

この文書を将来実装時の振り返り資料とする。
