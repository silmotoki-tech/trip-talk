## 現行の優先ルール

**最新の明示的なユーザー決定 > 過去の仕様・構想 > assistantの提案。**

過去のAPI＋Firebase構想は履歴として残すが、現行実装方針ではない。

## 主要意思決定

| ID | 決定/変更 | 理由・経緯 |
|---|---|---|
| D01 | 同じ場面・表現を反復する | 新場面を消化するより反射的に使う練習を重視 |
| D02 | 米語を学習基準、国際英語環境での意思疎通を優先 | 実際の旅行環境を重視 |
| D03 | 進行・難易度は本人が選ぶ | AIが自動進級・卒業判定しない |
| D04 | 台本数は先に固定しない | 作戦会議で獲得目標を洗い出して必要本数を逆算 |
| D05 | 質問力・リアクション・聞き返し・確認・言い換えを正式な学習対象にする | 受け答えだけでは会話力が不足する |
| D06 | 既習表現の自然な再登場を歓迎する | 複数場面で使う汎用表現を定着させる |
| D07 | 台本制作は教材DBを参照し、人間とAIの壁打ちで確定する | 単発の自動台本量産をしない |
| D08 | 学習の中心は台本／会話例の予習と反復 | ChatGPT Liveそのものを中心教材にしない |
| D09 | ChatGPT Liveは台本練習後の実戦練習として外部ChatGPTで使う | Trip TalkにRealtime APIを内蔵する前提ではない |
| D10 | 台本はTrip Talkアプリ側で自動生成しない | ChatGPT専用プロジェクトで戦略会議しながら設計する |
| D11 | 「台本作成」は過去データ確認 → 戦略会議 → 設計整理 → 台本作成の順 | GitHubの蓄積を次回教材へ反映するため |
| D12 | 台本確定後にTrip Talk GitHubへ保存し、将来は横断表現DBを再生成する | ChatGPTの記憶だけに依存しない |
| D13 | Trip TalkとTamoyan-Englishを厳密に分離する | 2026-09-09〜10にリポジトリを取り違えたため。書込前に対象リポジトリを確認する |
| D14 | 現在のホテル／空港の既存教材・シーン・語彙・会話例は新教材へ引き継がない | 新設計をMOTOKI0から組み直すため |
| D15 | 新教材はMOTOKI0から順番に作る | 過去教材を流用せず、新しい設計思想で積み上げる |

| D17 | M0ではUI大改修より先に教材データとコードを分離する | 今後の台本追加・DB生成・GitHub保存を安定させるため |
| D18 | 確定台本を正本、横断表現DBを派生データとする | 台本修正時のDB不整合を避ける |
| D19 | 旧Realtime API／Firebase中心ロードマップは現行方針から外す | 現在は外部ChatGPT Live利用が前提 |
| D20 | 2026-09-18時点でM0はGitHub mainに未反映 | 最新mainは `e4b820f`。再開時はM0から進める |
| D21 | 台本一覧は階層ナビを主役にせず、場面ラベル＋短いサマリー付きのフラット一覧を基本にする | 台本を探しやすくし、増えても階層が深くなりすぎないようにする |
| D22 | 1台本＝1学習単位。各ユーザーごとに音読回数・最終音読日時・4段階自己評価を持つ | 100回音読学習法に合わせ、細かい弱点分析より反復状況を見える化する |
| D23 | 音読カウンターは1回音読するごとに手動で+1し、その時刻を最終音読日時として更新する | 自分用アプリなので自動判定や厳密な不正防止は不要 |
| D24 | 4段階自己評価はいつでも本人が変更でき、評価済み台本も非表示にしない | AIが習得判定せず、本人が今後どう扱うかの目印にする |
| D25 | 台本を後から修正しても音読回数・最終日時・自己評価はリセットしない | 過去の練習も本人にとって有効な履歴として扱う |
| D26 | 台本本文は共有して双方が閲覧可能、練習履歴はタモやん／ちゃみごとに分離する | 共通教材と個人学習状態を分ける |
| D27 | Liveの詳細失敗ログをTrip Talkへ自動蓄積することはMVP要件にしない | 反復中心の学習思想を優先し、Live終了時の講評はその場で確認できればよい |
| D28 | 個人進捗はFirebase/Firestoreへ保存する | Safariの履歴・Webサイトデータ消去で進捗が消えないようにするため。GitHubは教材の正本、Firestoreは進捗の正本と役割分担する |
| D29 | FirebaseはLive・分析基盤としてではなく、進捗保存用途に限定して導入する | 過去のAPI＋Firebase構想を復活させるのではなく、音読回数・最終音読日時・4段階評価の永続化だけを目的とする |
| D30 | 各台本に「読み上げ用指示書」生成ボタンを用意する | 会話練習ではなく、質問→答え→質問→答えの台本をそのままChatGPT Liveに読ませ、聞き取り練習や発話できない場所での学習に使う |
| D31 | 読み上げモードでは台本を改変・要約せず、順番どおりに読み上げる | ロールプレイではなく教材音声として使うため。余計な質問や会話継続はしない |
| D32 | 読み上げ回数は 1回 / 3回 / 5回 / 10回 をワンタップで選べるようにする | ChatGPT Liveへ渡す指示書に選択した反復回数を埋め込み、聞き流し・反復ヒアリングをすぐ始められるようにする |

## 現行の開発順序

1. **M0**：旧教材を外し、新しい教材データ構造を作る。旧API/Firebase構想を現行方針から外す。
2. **M1**：新しい台本スキーマを確定する。
3. **M2**：横断表現DBの生成処理を作る。
4. **M3**：ChatGPT台本作成フロー → GitHub保存 → DB更新を接続する。
5. **M4**：必要に応じて練習UIを強化する。

詳細は `roadmap.md` と `script-design.md` を参照。

## 過去の開発履歴

文書追加前mainには、初期Trip Talk、GitHub Pages対応、会話例・語彙、ChatGPT Voice指示、scripted / variation等の実装履歴がある。
これらの存在は、現在の教材内容を新設計へ引き継ぐ決定を意味しない。

また、過去文書にはAPI＋FirebaseでLive・分析・履歴保存をアプリ内完結する構想が残っている。これは履歴であり、現在の実装許可・現行仕様ではない。
