### 再開手順
1. この文書とAGENTS.md、CLAUDE.mdを読み、最新の作業場所・HEAD・GitHub main・未コミット差分を確認する。
2. 後半の設計・意思決定・失敗・未解決事項を読み、現行ChatGPT指示書方式とAPI構想のどちらを進めるかを確認する。今回の資料作成をAPI実装の許可にしない。
3. 設定・端末の学習データを保全する。バックアップcheckoutへ自動的に開発正本を移さない。
4. 現行方式の改修なら、2人×各場面×両モードの表示・指示書・利用者別設定を必要な範囲で確認する。コード変更時はnpm run lint、npm run buildとPages用設定の確認を行う。
5. iPhoneでコピー成功／拒否時、設定再読込、利用者切替、Start待ち、一往復待ち、終了後の総評を実測する。コード上の指示と音声モデルの実動作は別々に記録する。
6. API方式を選ぶなら、後半のロードマップに沿い一場面の小さな一巡から。モデル・価格・接続方法は実装時の公式仕様で確認する。
7. 完了した変更、検証、未検証、公開SHA、運用上の残課題を末尾へ追記する。

- AIの自動進級や習得判定を本人の選択より優先しない。会話例の暗唱一致を意思疎通の正否にしない。
- 目標仕様を実装済みと書かない。型や保存関数の存在だけでLive・分析・クラウド同期完了と判断しない。
- localStorage.clear()や関連アプリのwipeAll()でテストデータを片付けない。自分が作ったテストキーだけを対象にする。
- ユーザーIDを勝手に改名・統合しない。表示名と保存キーの意味を分ける。
- 永続APIキー、個別の支払い情報、個人の会話原文、端末の履歴を公開リポジトリへ転記しない。
- 有料Realtimeの凍結を勝手に解除しない。Firebaseプロジェクトや認証方式を架空に補完しない。
- 既存コードや公開設定の変更を資料作成に混ぜない。

## 08 今後のロードマップ
更新日: 2026-09-07 / 版: 1.0
以下は今回の目標と現存コード差分から整理した再開案。完了済み工程とはみなさない。

### 0. 復元の確認
READMEを読み、ZIPとGit bundleを別の空フォルダへ復元する。ソースHEADとハッシュを確認。端末内データとWorkチャットを見つけたら原資料へ追加する。

### 1. 現行路線を選ぶ
API＋Firebase目標を実装するか、現在のtrip-talkのChatGPT指示書方式を維持するかを記録する。今回バックアップでは両方の状態を保存した。表示名（ゴンザエモン/ちゃみ）も確定する。

### 2. 目標仕様を小さな一巡に落とす
2人/2起点/任意予習/難易度/振り返り/次巡選択の画面とデータ境界を固める。既存の例文・語彙は再利用できる候補。自動進級は追加しない。

### 3. Live接続を一つの場面で検証
サーバー側秘密管理、利用者確認、iPhone音声入出力、開始/終了/中断、5〜10分、重大ミスのみ訂正、日本語/パスを確認。モデル・価格・接続方法はその時点の公式資料で確認。
API利用量と1巡の実測コストを記録し、過去の入金から残高を推定しない。

### 4. 振り返りと次巡への反映
会話ログ保存→通常API分析→各項目表示→重点課題生成→本人選択→起点リセットを接続。
失敗時もログを残して再試行できるようにする。全改善点と重点課題を混同しない。

### 5. 2人の分離と反復試用
認証と保存権限を検証。各シナリオを複数巡（過去提案の目安は5〜10巡）試す。前巡の課題が戻るか、相づち・聞き返しが練習されるか、勝手に範囲が広がらないかを見る。

### 6. 運用・バックアップ
エラー/意思決定/変更履歴を更新。コード、プロンプト、スキーマ、端末/クラウドデータの書出しを定期的に同じ場所へ追加。秘密情報は別の安全な管理先で保持する。自動定期バックアップは今回設定していない。

### 7. MVP後
本人が必要と感じた順に「これを覚えたい」、履歴一覧/グラフ、表現ファミリー、汎用表現の累積、発音評価、場面追加を検討。
以前の「約30時間」は復元チャット中の粗い見積もりで、工数の範囲も確定していない。今回納期・費用の確約には使わない。
